# ADR 0001 — Charter-bounded self-directed loop

Status: Accepted
Date: 2026-07-27

## Context

Today the hustle loop executes a human-authored plan (`GOAL.md`, written via
`/grill-goal`) and **stops** when every increment is checked and the Definition
of Done is met (`STATUS: COMPLETE`, honoured by `hustle-session.sh`). We want the
loop to keep working after the plan is exhausted by **setting itself new goals**,
running until a deadline date or indefinitely.

An unattended agent that commits and pushes on its own
(`HUSTLE_SKIP_PERMISSIONS=true`) with no standing boundary invites goal-drift,
busywork, and destructive edits with no human watching. Open-ended runtime is
only safe when it is open-ended *within a fixed mandate*.

## Decision

Adopt a **charter-bounded** model. Split the single `GOAL.md` into two layers:

- **`CHARTER.md`** — stable, human-owned. Mission/theme, hard constraints,
  termination policy (deadline or infinite), and the standard for judging
  self-generated goals. This is what the human grills into shape.
- **`GOAL.md`** — bot-owned, regenerable, optional at rest. Holds the current
  Plan, derived from the Charter by a **goal-generation** phase.

`/grill-goal` shifts from "write the plan" to "write the Charter"; the `GOAL.md`
becomes optional and is (re)generated by the loop. Goal generation runs whenever
no active Plan exists — initially and after each Plan is exhausted — so plan
exhaustion no longer stops the chain; only the termination policy does.

## Consequences

- New human interview target: the Charter, not the plan increments.
- `/advance-goal` gains a branch: when the Plan is exhausted, run goal generation
  against the Charter instead of writing `STATUS: COMPLETE` — unless the
  termination policy has fired.
- Safety of the self-generated goals now rests on the Charter's constraints
  (open questions: approval gate vs. fully autonomous; how the deadline is
  checked). Tracked in later ADRs.
